# Open Local versus Verified MCP

Diagrams for Agents is one product with two explicit trust boundaries.

The open skill is the acquisition and trust surface. It should be useful without an account, inspectable without faith, and easy to share. Verified MCP is the dependable visual-intelligence layer for work that needs broader automatic selection, stronger validation, or application integration.

## What stays open

- The installable Agent Skill and plugin manifests.
- Visual-selection guidance for the bounded local catalogue.
- Seventeen deterministic local primitives and their schemas.
- The portable brand profile and decision brief contract.
- Source-editable HTML, standalone SVG, embedded JSON specifications, and receipts.
- Local Mermaid flow import, artifact validation, examples, and safety tests.
- Privacy by default: local rendering makes no content network request.

This is intentionally a complete useful loop: install, make a real artifact, inspect it, adapt it, and share it.

## What stays MCP and API driven

- Automatic representation selection across the broader supported catalogue.
- The 341-framework reference ontology and its production selection policy.
- Stronger evidence and schema validation with repair behavior.
- Routing and fallback across nine confirmed rendering engines.
- Hosted renderer operations, updates, compatibility, and observability.
- Stable `VisualPayload` responses, hosted viewer links, SVG/PNG delivery, keys, quotas, and product integration.

These capabilities benefit from central operation: the selection policy improves, renderer availability changes, validation rules evolve, and applications need a contract they can depend on.

## The promise at each boundary

| | Open Local | Verified MCP + API |
| --- | --- | --- |
| Job | Help an agent make a useful private diagram now | Supply broad, dependable visual judgment to agents and products |
| User chooses | Whether content stays local and which approved brand profile applies | Whether to send content to the configured service |
| System chooses | Among 17 bounded primitives using open guidance | Across 35 supported families and nine engines using the hosted selector |
| Validation | Structural safety and exact-source checks where required | Server-side evidence, schema, selection, and renderer validation |
| Output | Ownable local artifact | Stable application payload plus hosted artifacts |

## Product rule

Open enough capability that a cold user can experience the idea, make something worth sharing, and trust how it works. Keep the operationally expensive and continuously improving intelligence layer hosted. Never silently move a local request across that boundary.
